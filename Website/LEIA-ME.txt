ACESSIFOOD — SITE + DESKTOP COM SUPABASE

O projeto usa o Supabase (PostgreSQL) como fonte compartilhada de dados. O site e o aplicativo Electron usam a mesma URL de projeto e a mesma chave pública publishable/anon. Não é necessário configurar MySQL nem executar uma API Node própria.

PASTAS E ARQUIVOS
- index.html, style.css e app.js: site.
- supabase-config.js: URL e chave pública do Supabase usadas pelo navegador.
- supabase-sync.js: leitura, gravação e atualização periódica do estado compartilhado.
- desktop/: aplicativo Electron do vendedor.
- desktop/schema.sql: tabelas e função PostgreSQL a executar no Supabase SQL Editor.
- downloads/: pacotes baixáveis exibidos no site.

1. PREPARAR O BANCO
1. Abra https://supabase.com/dashboard e selecione o projeto.
2. Abra SQL Editor > New query.
3. Abra desktop/schema.sql, copie o conteúdo para a consulta SQL e execute.
4. Em Project Settings > API (ou Connect), copie a Project URL e a chave pública publishable/anon. Não copie a secret/service_role key.

2. CONFIGURAR O SITE
1. Abra supabase-config.js.
2. Substitua https://SEU-PROJETO.supabase.co pela URL do projeto.
3. Substitua SUA_CHAVE_PUBLISHABLE_OU_ANON pela chave pública do projeto.
4. Abra a pasta do site por HTTP local (por exemplo, python -m http.server 5500) ou hospede-a em HTTPS.

3. CONFIGURAR O DESKTOP
1. Entre na pasta desktop.
2. Copie .env.example para .env.
3. Preencha SUPABASE_URL e SUPABASE_ANON_KEY com os mesmos valores do site.
4. No terminal, dentro da pasta desktop, execute npm install e depois npm start.

4. COMO A SINCRONIZAÇÃO FUNCIONA
O site e o Desktop usam a tabela public.acessifood_state para sincronizar o estado da aplicação. As tabelas public.loja e public.produto guardam os cadastros relacionais de lojas e produtos. O Desktop consulta o Supabase pela API HTTPS; não precisa de conexão direta ao servidor PostgreSQL nem de senha de banco.

SEGURANÇA — LEIA ANTES DE PUBLICAR
O schema.sql deste protótipo cria policies RLS de demonstração sem login para facilitar a sincronização durante o desenvolvimento. Isso significa que qualquer pessoa com a chave pública e acesso à API pode ler ou alterar os dados dessas tabelas. Use apenas informações fictícias. Antes de usar com clientes reais, implemente Supabase Auth e policies RLS que restrinjam cada registro ao usuário autorizado. Nunca coloque uma chave secret/service_role em supabase-config.js ou desktop/.env. A chave do cliente deve ser publishable/anon.

NOTAS
- Pagamentos e entregas continuam demonstrativos.
- O pacote Desktop contém código-fonte Electron, não um instalador nativo .EXE/.DMG.
- Caso o site não carregue a biblioteca do Supabase, confira a conexão com a internet, pois o cliente web é carregado por CDN.
